# 页面视觉模式

在选择、修改或扩展页面的默认视觉构图时读取。

`page-types.md` 定义页面为什么存在；本文件定义该 Page Type 默认怎样呈现；`assets/template/` 中的 renderer、token 和 CSS 决定精确结果。

不要在本文重复 CSS 数值。需要调整字号、间距或比例时直接修改模板实现，并确认这里描述的结构和行为仍然成立。

## 共享页面框架

`content` 和 `evidence` 使用标准页面框架：

1. 顶部标题占满安全内容宽度；
2. 核心观点紧随标题并自然换行；
3. 主体区域占据剩余空间；
4. Footer 固定在安全区底部，只显示品牌身份和页码。

`cover`、`section` 和 `summary` 使用各自的稳定构图，不通过内容页坐标补丁模拟。

## Cover

- 使用全画布品牌色与一张主要背景图建立第一视觉。
- 品牌标识位于顶部，标题组位于视觉中心，演示者和日期位于底部。
- 标题是页面最强信息；副标题只补充一句说明。
- 不显示标准 Footer、目录、指标组或内容组件。
- 背景图允许裁切，但必须保留稳定的文字可读区域。

实现来源：`renderCover()`、`.slide-cover` 与 `.cover-*`。

## Section

- 左侧为独立章节编号区，右侧为标题和一句描述。
- 编号区与内容区之间使用品牌色竖线建立转折。
- 编号、分隔线和完整文字组共同垂直居中。
- 编号不使用圆形、底色或卡片容器。
- 字体沿用当前模板尺度；历史样例只能提供构图参考，不能覆盖模板字体系统。
- 保留标准 Footer。

实现来源：`renderSection()`、`.slide-section` 与 `.section-*`。

## Content

- 使用共享页面框架，主体只承载一个 `component.kind`。
- 页面标题和核心观点负责说明判断，组件负责表达信息关系。
- 不在同一页并列多个互不相关的组件。
- 组件不得突破主体区域或侵入 Footer。

实现来源：`renderContent()`、`standardFrame()` 和 `styles/components.css`。

## Evidence

- 使用共享页面框架，主体默认由主要证据和解释区组成。
- 证据是更大的视觉区域；解释区只说明看什么以及它说明什么。
- 每页只提供一个证据对象：使用 `media` 承载图片或视频，或者使用 `component` 承载 `chart` 或 `table`；两者不能同时出现。
- 图片、截图或视频必须放入稳定 Media Surface，并显示必要标题、来源或说明。
- Media Surface 根据素材使用 `16:9`、`3:4` 或 `9:16`，竖版素材不会改变整张 Slide 的 16:9 画布。
- 视频使用本地资源和原生 controls，打印时使用 poster 替代。
- 图表和表格继续复用对应 Content Component 的数据契约与视觉规则，不在 Evidence 中建立第二套 renderer。
- 默认完整展示证据；只有裁切不会损害含义时才使用 `cover`。

实现来源：`renderEvidence()`、`renderComponent()`、`.evidence-layout` 与 `.evidence-*`。

## Summary

- 使用整页品牌色背景，左右等分承载总结命题和 2–4 个结论。
- 左右两侧各自垂直居中，不使用中心对称比较结构。
- 结论、编号、Footer 品牌身份和页码统一使用品牌前景色层级，保证整页对比度一致。
- 结论使用统一编号和文字层级，不加入新证据或新概念。

实现来源：`renderSummary()`、`.slide-summary` 与 `.summary-*`。

## 扩展页面视觉模式

只有现有五种模式无法稳定承载新的 Page Type 时才扩展：

1. 先在 `page-types.md` 定义新的叙事职责；
2. 在本文定义默认视觉结构、可选区域和溢出行为；
3. 在模板中补齐 renderer、CSS、深浅主题和打印实现；
4. 在 `quality-gates.md` 增加能够发现回归的验收项。

只改变左右比例、对齐或组件组合时，优先建立已有模式的明确变体，不新增 Page Type。
