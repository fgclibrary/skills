# 页面类型

在判断一页为什么存在、选择页面框架或新增页面类型时读取。

Page Type 表达叙事职责，不由页面使用了表格、指标、流程或图表来决定。

## Cover

用于建立主题、身份和品牌。

- 只保留主题、必要说明和身份信息；
- 不堆放议程、指标或多个结论；
- 标题过长时优先改写，不持续缩小字号。

## Section

用于标记真实章节转折。

- 内容保持简短，形成节奏停顿；
- 标题不使用命令式或教学式口吻；
- 描述负责说明本章关注范围，不复述标题。

## Content

用于展开一个主要判断，并用一个内容组件解释其信息关系。

- 标题和核心观点先说明本页要表达什么；
- 主体只选择一个与信息关系匹配的组件；
- 不把多个互不相关的模块拼成 Dashboard。

## Evidence

用于让一个主要证据对象解释判断。

- 主体可以是图片、视频、图表或数据表格；
- 一页只保留一个主证据对象；
- 说明区负责引导观看，不与证据争夺视觉中心。

## Summary

用于收束演示并明确下一步。

- 总结 2–4 个可记忆结论；
- 需要行动时说明行动对象和下一步；
- 不在结尾重新引入尚未解释的新概念。

## 新增页面类型

只有新的叙事职责无法由现有类型承担时才新增。

新增前回答：

1. 它解决什么重复出现的叙事问题？
2. 为什么现有 Page Type 加 Content Component 无法表达？
3. 它需要什么稳定的数据契约？
4. 它如何适配主题、全屏和打印？

仅仅因为构图不同，不足以建立新的 Page Type。
