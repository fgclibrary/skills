# Process

在表达真实先后顺序、阶段推进或节点交接时读取。

## 使用边界

- 适合 3–5 个具有明确方向的步骤或阶段。
- 不用于等权分类、能力清单或不存在推进关系的成熟度状态。
- 关系重点是依赖而不是顺序时，使用 Diagram。

## 数据契约

```js
{
  kind: "process",
  steps: [
    {
      index: "01",
      title: "步骤名称",
      description: "该步骤完成的事情。",
      state: "complete",
    },
  ],
}
```

- `index`、`title` 和 `description` 为必需字段。
- `state` 可选值为 `complete`、`current` 或 `upcoming`，默认 `upcoming`。
- 状态只表达演示所讨论的真实进度，不用于装饰性配色。

## 默认视觉行为

- 使用单向水平流程线和等距节点。
- 节点编号位于流程线上，标题在上、描述在下并保持统一位置。
- `complete` 与 `current` 使用品牌色实心节点，`upcoming` 使用开放节点。
- 文本采用居中对齐，因为它直接归属于对应节点。

## 内容与溢出

- 默认 3–5 步；超过 5 步时分阶段或拆页。
- 标题保持一行，描述保持一到两行。
- 不通过缩小节点、压缩行高或延长流程线容纳更多步骤。

## 验收

- 每条相邻关系都代表真实顺序或交接。
- 节点、标题和描述与流程线对齐。
- `complete` / `current` 与 `upcoming` 在深浅主题和打印状态下仍可区分。

实现来源：`renderProcess()`、`.process` 与 `.process-step`。
